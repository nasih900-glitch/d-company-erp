# Code 30.4 PS5 participant billing and package-amendment patch

Migration 0083 records friends who join a fixed-price PS5 session after Start. Forward migration 0084 prevents the session's participant revision from decreasing at the database boundary. Migration 0085 is the current head and adds one immutable 60-to-30-minute PS5 package-amendment receipt plus a monotonic billing revision. The booked billing customer, original package snapshots, paid extension receipts, and original `extra_controllers` snapshot remain unchanged.

Each Join creates a tenant-scoped presence interval for one live saved customer. Leave closes that interval once. The live count is derived from open intervals under the locked session row; the physical cap is four players including the booked Single or Dual count and any upfront extra controllers. Join requires an active, unbilled, complete-snapshot PS5 package session and open source shift. Leave also works while paused, using the pause-excluding play meter.

The backend contract is:

- `GET /api/v1/gaming/sessions/{session_id}/participants` returns `session_id`, `participant_revision`, derived `active_friend_count`, `current_player_count`, `max_player_count=4`, and interval rows containing IDs, customer IDs, join/leave times, play meters, and revisions.
- `POST /api/v1/gaming/sessions/{session_id}/participants/join` accepts `expected_participant_revision`, either `customer_id` or `customer_name` plus `customer_phone`, directory fence fields, and the optional all-or-none offline trio `occurred_at`, `play_elapsed_ms`, `expected_pause_version`.
- `POST /api/v1/gaming/sessions/{session_id}/participants/{participant_id}/leave` accepts `expected_participant_revision` and the same optional offline trio.
- `POST /api/v1/gaming/sessions/{session_id}/stop` accepts `expected_participant_revision` and the existing optional offline `ended_at`. Once a roster event exists, the revision is mandatory.
- `POST /api/v1/gaming/sessions/{session_id}/amend-package` accepts `target_package_id`, exact current CAS fields (`expected_timer_minutes`, `expected_amount_minor`, `expected_pause_version`, `expected_participant_revision`, and `expected_billing_revision`), and target tariff snapshots (`expected_target_price_minor`, `expected_target_duration_minutes`, and `expected_target_variant`). The optional offline pair `occurred_at` plus `play_elapsed_ms` is all-or-none and uses the existing offline-capture headers.

The amendment endpoint is limited to an active or paused, unbilled, complete-snapshot PS5 Single or Dual 60-minute booking before 30:00 of pause-excluded play. It requires participant and billing revision zero, no saved participant evidence, no paid extension, no POS order, an open source shift on the same branch and terminal, and the matching active published 30-minute tariff: ₹80 Single or ₹100 Dual. The 30-minute controller surcharge preserves the original upfront controller count. The response keeps the original `package_*_snapshot` fields and separately returns `billing_revision=1` plus the `effective_package_*` fields. Later friends and paid extensions are allowed when they supply billing revision 1.

Stop and extension accept `expected_billing_revision`. It remains optional only for an unamended revision-zero session so the deployed clients retain their old behavior. Once a receipt exists, an absent or stale revision fails closed. POS handoff, participant changes, Stop, receipts, and customer playtime validate or consume the immutable effective tariff; receipt history exposes original and effective tariff fields separately.

Every roster write carries `expected_participant_revision` and a durable idempotency key. Offline Join/Leave additionally carries `occurred_at`, `play_elapsed_ms`, and `expected_pause_version`, bound to the existing offline provenance headers. Captured events must follow the last accepted participant and pause transitions. Audit and replay payloads contain customer IDs but no names or phone numbers.

The pause clock now freezes play time at the recorded pause boundary and preserves that exact meter when Resume or Stop folds the open pause into `paused_duration_ms`. This prevents a one-millisecond flooring drift from rejecting valid historical offline Join/Leave meters or changing a paused friend's settlement.

Stop requires the exact current participant revision after the first roster event. Under the session lock it closes open intervals, sums each customer's pause-excluded milliseconds across all rejoins, rounds that customer once to started hours, and charges ₹30 per started hour with a ₹30 minimum. The immutable settlement header retains the Stop key, request hash, actor, terminal, amount before, surcharge, and amount after; immutable customer lines retain actual playtime and charge. POS remains one Gaming line whose note shows base plus extensions separately from the friend surcharge. Participant playtime appears in customer history and leaderboard totals with zero qualifying paid minutes and zero draft reward.

Android Room 53 implements the required per-session FIFO ledger for amendment, Join, Leave, extension, and Stop. Each captured action receives the next sequence number inside one Room transaction; sync drains actions in `(session, sequence)` order, persists the returned participant and billing revisions, and blocks every later action of that session, including Stop, while an earlier action is rejected or its response is ambiguous. Ambiguous actions are retried in order with the same idempotency key. The backend rejects known revision gaps and accepted actions captured before an amendment, but it cannot detect an earlier action that still exists only on an offline device, so FIFO upload and post-acknowledgement Stop remain release requirements that the tablet enforces.

Join/Leave is not enabled for hourly, non-PS5, legacy ambiguous, or incomplete-snapshot sessions. Join while paused is rejected until Resume. Web and Android expose the same package-change, friend, extension and Stop actions; the server remains authoritative for every total.

Rollback before business resumes should restore the pre-0083 database snapshot and matching application build. After participant rows, settlements, or package-amendment receipts exist, do not run the predecessor application or downgrade below migration 0085: the predecessor cannot validate or bill that evidence. Retire the feature only through a reviewed, audited migration that preserves all interval, settlement, and amendment history.

# Code30.1 targeted patch candidate

Code30.1 keeps the existing Code30 application and includes two Android fixes found during the isolated September 14 gaming and billing trial, the customer-deletion replay correction found before signing, and the narrow shared routine-operation correction verified with two authorized users. Its current technical candidate identity is v3.1.28, installation build 36, Room schema 48 and backend migration head 0073. The immutable v3.1.26/build 34 tag failed three stale backend release-test expectations before signing. The v3.1.27/build 35 tag was cancelled before signing after deletion-replay defects were reproduced. Both remain failed-attempt history and are not accepted packages. Earlier tags and signed APK bytes remain immutable. The higher integer build allows Android to install this patch over Code30 build 33.

A Stop explicitly rejected because its captured time is in the future can now be retried after the clock is corrected. Recovery keeps the same session and retry identity and preserves the original rejected timestamp. Stops with uncertain network outcomes retain their original captured time. No other rejection or completed session is rewritten.

Gaming attention now includes rejected Start and Stop actions. Review selects the affected station without automatically retrying an action. Rejected Send remains represented once in payment attention.

Customer deletion now advances a tenant-scoped, PII-free directory revision under a consistent lock order. Phone-based customer creation, linking and name fill must present the exact revision captured with the original action; stable customer-ID bookkeeping remains valid. Android Room 48 and the Web retry journal preserve this evidence across offline queues, acknowledgement loss, restart and retry. Migrated legacy actions keep their historical request identity and fail safely after a deletion. Fresh intentional recreation remains valid after the current directory revision is observed. Alembic 0073 preserves the monotonic counter through ordinary cleanup and refuses a data-losing downgrade after the fence has been used.

Routine POS and gaming work now resolves the exact company, branch and terminal shift without requiring the acting user to be its opener. An authorized second user can continue, stop, hand off and pay another user’s gaming session and can close that exact shift; audit fields retain every actor. Refund, void and privileged discount paths keep their separate permissions and safeguards.

The original functional patch passed 1,066 JVM tests and 53 Room/Compose tests on the isolated API-35 emulator. Nine complete synthetic gaming bills reconciled to INR 599, including actual 15-minute expiry, paid extension, paused-time exclusion, an offline Stop across restart, a lost payment acknowledgement followed by recovery, hourly rounding, an additional controller, and all five pricing-card modes. The trial shift closed with zero cash variance; all nine stations were available. A separate two-user transaction produced one exact INR 140 receipt, two mutually closed shifts and zero variance, open shifts, active sessions or blocked stations while retaining each actor.

The expanded candidate passes 1,514 backend tests, 507 Web tests, 1,072 JVM tests in each of four Android variants, 7 audit-driver tests and 674 root release-contract tests with 2 environment skips. Release/direct-release lint and unsigned local APK/AAB assembly passed. API-35 instrumentation completed 322 cases with 320 passes, 2 guarded permission skips and zero failures; both skipped notification/exact-alarm cases passed separately after granting their required permissions. Targeted Room 47 to 48 instrumentation preserved every legacy queued-customer field and left the new token and directory evidence null; both legacy and current stale retries were rejected without recreating deleted PII, while a fresh same-phone Web recreation using the observed revision succeeded. Fresh v3.1.28 tagged CI, protected signing, signed upgrade verification and release staging remain separate gates and must be recorded from actual results.

The physical Redmi Pad 2 is unavailable. Emulator evidence does not establish its keyboard, alarm, battery or printer behavior, or constitute a whole-day physical shop trial. Rewards and WhatsApp remain inactive. Production Android offer/minimum-version policy and the pause feature flag are unchanged by this patch. This document does not claim deployment, an offered update or physical installation.

# Build 78 / 3.1.71 candidate

Build 78 retains Build 77's features, Android interactions and selected-tablet
normal-close admission. Room remains 58 and Alembic remains 0105. The new image
change pins authenticated Alpine3.24 OpenSSL packages to `3.5.9-r1` in the
backend, frontend and PostgreSQL images, including `openssl-dev` in the isolated
CPython hashlib builder. Installed-package checks require that same revision.
The upstream OpenSSL version remains 3.5.9; the Alpine revision carries vendor
security backports. No scanner threshold or dependency-lock relaxation is used.

The vendor source revision is
[`0f4c7e8d0f5f7cebbdc2156eca4391080b732bf2`](https://gitlab.alpinelinux.org/alpine/aports/-/commit/0f4c7e8d0f5f7cebbdc2156eca4391080b732bf2).
Exact package availability, authenticated APK installation, independent builds
and raw scans are separate required evidence. A source pin alone does not
establish a clean image or a deployed release.

Build 77 / v3.1.70 at `f3178f70b4994c46fd0d2e48af76bbb7606c941b`
and all earlier tagged source, assets and literal freeze maps remain immutable.
Current staging and installation require the coordinated successor identity.

## Security evidence boundaries

Caddy remains on its exact Alpine3.23 OpenSSL `3.5.9-r0` runtime and separately
reviewed static-Go execution-path assessment. Its current source/composition
bindings are refreshed mechanically; runtime hashes and scanner findings stay
unchanged. The backend/frontend/PostgreSQL r0 assessment records, native hashes,
source hashes and raw finding fixtures remain historical. They are not relabeled
r1 and do not admit current r1 source. Their regression tests use immutable
Build 77 deployment bytes and explicitly reject current-source admission.

The existing scanner pipeline already accepts a genuine raw zero-High result.
For the backend's separately proven CPython hashlib backport, it can prove and
filter that single fixed finding without any OpenSSL exception. Unknown High
findings, changed runtime proof, fabricated ignores and non-equivalent rescans
remain blocking. There is no new r1 VEX statement or generic CVE exception.
The deterministic hashlib binary hash and controls remain unchanged and must
be corroborated by the r1 build. PostgreSQL's live configuration/catalogue
admission check remains mandatory independently of the image scan.

## Tablet, production and release admission

The existing `verify-build77-tablet-close.sql` and selected-tablet validator are
unchanged. The original fresh known-zero Build 71 report path remains. Its
alternate path requires a fresh readonly snapshot of the exact installation,
company/terminal and newest shift, one completed normal Build 71 Android close
by its real closer, matching opening/closing action suffix and known-zero sync
during or after that shift. No age cap applies to a qualifying normal close.
Unknown/nonzero reports, recovery closes, ambiguity, newer/open shifts or live
business activity refuse admission. Audit time may precede closed_at in the
same transaction. Selected snapshots still bracket fleet/global reports in
both running and stopped phases.

A normal close proves its exact shift only. Historical zero-report evidence
does not prove later local work is absent. Compatible replay, retained legacy
queues, optional updates, signed in-place upgrade preservation, exact runtime,
Redis retention, restore/rollback and idle-shop checks remain required. Nothing
in this successor force-closes a shift or discards tablet work.

The protected exact-source workflow is authoritative before signing or offering;
its reviewed tag may start while branch CI is in progress. All complete root,
backend/frontend, both image-store security, Android instrumentation/unit/lint
and independent reproduction gates remain. Signed upgrade and production/tablet
admission remain required before an optional update is offered. Prior TCL motion
and focus evidence does not establish a newly signed Build 78 or live Redmi
acceptance, and no zero-stutter claim is made.
